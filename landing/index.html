یک فراخوانی

دامنه‌ی شما به POST /api/v1/payments درخواست می‌زند، کاربر را به لینک پرداخت می‌برد و نتیجه‌ی امضاشده را دریافت می‌کند.

شروع سریع — سمت دامنه‌ی پذیرنده
require 'WebiroGateway.php';

$gateway = new WebiroGateway('https://webiro.ir/gateway', 'wgr_...', 'wgs_...');

// ۱) ایجاد پرداخت و هدایت کاربر (ریال یا تومان، هر درگاهی)
$payment = $gateway->requestPayment([
    'amount'       => 250000,   // تومان
    'currency'     => 'toman',
    'gateway'      => 'auto',    // یا oxapay برای کریپتو
    'order_id'     => 'ORD-101',
    'callback_url' => 'https://lahze-app.ir/payment/result',
]);
header('Location: ' . $payment['payment_url']);

// ۲) در صفحه‌ی بازگشت — امضا تایید می‌شود، دستکاری رد می‌شود
$result = $gateway->verifyRedirect();
if ($result['ok']) { /* سفارش را پرداخت‌شده کنید */ }
امنیت

پول جدی است؛ امنیت هم همین‌طور

تایید سمت سرور: نتیجه همیشه با استعلام مستقیم از بانک/تامین‌کننده تایید می‌شود، نه با پارامترهای مرورگر.
امضای HMAC-SHA256: ریدایرکت بازگشت و وبهوک هر دو امضا دارند؛ دستکاری مبلغ یا وضعیت قابل تشخیص است.
وب‌هوک کریپتو با HMAC-SHA512: امضای نامعتبر به‌طور کامل نادیده گرفته می‌شود و هرگز تراکنش را نمی‌کُشد.
تطبیق اجباری مبلغ: مبلغ تاییدشده‌ی بانک باید دقیقاً برابر تراکنش باشد؛ مغایرت = شکست (+ برگشت وجه خودکار در سامان).
نهایی‌سازی اتمیک: callback تکراری بانک دو بار «پرداخت موفق» نمی‌سازد؛ همه‌چیز idempotent است.
جداسازی پذیرنده‌ها: هر کلید فقط تراکنش‌های خودش را می‌بیند و فقط به دامنه‌ی خودش callback می‌دهد.
حریم خصوصی: شماره کارت فقط ماسک‌شده ذخیره می‌شود و لاگ‌ها مقادیر حساس را مخفی می‌کنند.
Rate limit: محدودیت پیش‌فرض ۶۰ درخواست API در دقیقه برای هر IP.
