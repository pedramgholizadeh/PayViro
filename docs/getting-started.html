Webiro Gateway

نصب و راه‌اندازی

گیت‌وی روی هاست سی‌پنل شما (webiro.ir) نصب می‌شود؛ طراحی‌شده برای هاست اشتراکی، بدون Composer و بدون دسترسی روت.

پیش‌نیازها#

نیازجزئیات
PHP 7.4+PHP 8.x هم کاملاً پشتیبانی می‌شود. از MultiPHP Manager سی‌پنل انتخاب کنید.
اکستنشن‌های PHPcurl و PDO اجباری · pdo_sqlite (پیش‌فرض) یا pdo_mysql · soap فقط برای درگاه سامان
HTTPSگواهی SSL روی webiro.ir فعال باشد (AutoSSL/Let's Encrypt کافی است).
فضاکمتر از ۲ مگابایت.

۱) آپلود روی سی‌پنل#

محتویات پوشه‌ی webiro-gateway را داخل public_html/gateway/ آپلود کنید تا ساختار به این شکل باشد:

ساختار پوشه‌ها
public_html/
└── gateway/
    ├── .htaccess          ← روتینگ و مسدودسازی مسیرهای داخلی
    ├── index.php          ← front controller
    ├── admin/             ← پنل مدیریت
    ├── docs/              ← همین مستندات
    ├── config/            ← کانفیگ (از وب مسدود است)
    ├── data/              ← دیتابیس SQLite (از وب مسدود است)
    ├── logs/              ← لاگ‌ها (از وب مسدود است)
    ├── src/               ← کد منبع (از وب مسدود است)
    ├── sdk/               ← SDK برای دامنه‌های دیگر (از وب مسدود است)
    └── tools/             ← ابزار کلیدساز (از وب مسدود است)

نکته: مسیرهای config، data، logs، src، sdk و tools با .htaccess از دسترسی وب مسدود شده‌اند. فقط index.php، admin/ و docs/ عمومی هستند.

۲) ساخت فایل کانفیگ#

از File Manager سی‌پنل (یا SSH) یک کپی از فایل نمونه بسازید و مقادیر CHANGE_ME را پر کنید:

SSH
cd ~/public_html/gateway
cp config/config.example.php config/config.php
nano config/config.php

مهم‌ترین مقادیر:

کلیدتوضیح
app.base_urlhttps://webiro.ir/gateway — دقیقاً با همین مسیر، بدون اسلش انتهایی.
admin.username / admin.passwordاطلاعات ورود پنل مدیریت — یک رمز قوی بگذارید.
cron.keyکلید فراخوانی کرون وبهوک — یک رشته‌ی تصادفی.
drivers.*اعتبارنامه‌ی درگاه‌ها — راهنمای هر درگاه.
db.driversqlite (پیش‌فرض، بدون تنظیم) یا mysql با مشخصات دیتابیس سی‌پنل.

۳) سطح دسترسی#

پوشه‌های data و logs باید برای کاربر PHP قابل نوشتن باشند (در سی‌پنل معمولاً همان مالک است و کاری لازم نیست). اگر خطای «permission» دیدید، Permission این دو پوشه را روی 755 بگذارید.

۴) ساخت کلید برای دامنه‌ها#

برای هر دامنه‌ی پذیرنده یک کلید بسازید و تکه‌ی خروجی را در merchants کانفیگ اضافه کنید:

SSH
php tools/make-api-key.php "lahze-app"  "https://lahze-app.ir"
php tools/make-api-key.php "webirox"    "https://webirox.ir"

محدودیت دامنه: فیلد callback_domain هر پذیرنده، دامنه‌ی مجاز آدرس بازگشت را قفل می‌کند. یعنی کلید lahze-app.ir روی دامنه‌ی دیگری کار نمی‌کند — حتی اگر لو رود.

۵) تست بدون پول (درگاه سندباکس)#

تا وقتی اعتبارنامه‌ی بانکی ست نشده، از درگاه داخلی test استفاده کنید. این درگاه یک شبیه‌ساز بانک دارد و همه‌ی مراحل — callback، verify، وبهوک و امضا — را واقعاً اجرا می‌کند:

cURL
curl -X POST https://webiro.ir/gateway/api/v1/payments \
  -H "X-API-Key: wgr_..." -H "Content-Type: application/json" \
  -d '{"amount": 1500000, "gateway": "test",
        "callback_url": "https://lahze-app.ir/payment/result",
        "order_id": "TEST-1"}'

# payment_url را در مرورگر باز کنید → صفحه‌ی شبیه‌ساز بانک

۶) کرون وبهوک (سی‌پنل)#

اگر سرور پذیرنده هنگام ارسال وبهوک در دسترس نباشد، گیت‌وی با فاصله‌های ۱، ۵، ۱۵، ۶۰ و ۲۴۰ دقیقه دوباره تلاش می‌کند. برای اینکه این تلاش‌ها خودکار اجرا شوند، در سی‌پنل → Cron Jobs یک کار هر ۵ دقیقه اضافه کنید:

Cron command
wget -q -O /dev/null "https://webiro.ir/gateway/api/cron/webhooks?key=YOUR_CRON_KEY"

این کرون علاوه بر وبهوک‌های معوق، تراکنش‌های منقضی‌شده را هم نهایی می‌کند.

چک‌لیست قبل از پروداکشن#

  • config/config.php ساخته و همه‌ی CHANGE_MEها پر شده‌اند؟
  • رمز پنل مدیریت قوی است و کلید cron.key تصادفی است؟
  • درگاه test در پروداکشن بسته شده؟ (drivers.test.enabled = false)
  • کرون وبهوک ست شده و یک‌بار دستی تست شده؟
  • با یک پرداخت واقعی کوچک، چرخه‌ی کامل (پرداخت → callback → وبهوک → استعلام) تست شده؟
  • بکاپ دوره‌ای از data/gateway.sqlite (یا دیتابیس MySQL) تنظیم شده؟
