امنیت و امضا

هر کانال اطلاع‌رسانی نتیجه‌ی پرداخت (ریدایرکت و وبهوک) با HMAC-SHA256 امضا می‌شود و تایید پرداخت همیشه سمت سرور و با استعلام مستقیم از بانک انجام می‌شود.

دو کانال نتیجه، یک منبع حقیقت#

ریدایرکت (Callback)وبهوک (Server-to-Server)
مخاطبمرورگر کاربرسرور شما
اعتمادپذیریخوب (با امضا)عالی — مستقل از مرورگر

«منبع حقیقت» همیشه وضعیت خود گیت‌وی است که با استعلام از بانک ساخته می‌شود: GET /api/v1/payments/{token}.

امضای ریدایرکت#

پارامتر sig با کلید secret پذیرنده ساخته می‌شود. رشته‌ی ورودی HMAC به‌ترتیبِ زیر از هفت مقدار با جداکننده | ساخته می‌شود:

Canonical string
token | order_id | amount | status | ref_no | card_no | gateway
تایید دستی (بدون SDK)
$expected = hash_hmac('sha256', implode('|', [
    $_GET['token']   ?? '',
    $_GET['order_id'] ?? '',
    $_GET['amount']   ?? '',
    $_GET['status']   ?? '',
    $_GET['ref_no']   ?? '',
    $_GET['card_no']  ?? '',
    $_GET['gateway']  ?? '',
], $secret);

if (!hash_equals($expected, $_GET['sig'] ?? '')) {
    http_response_code(400);
    exit('امضا نامعتبر است');
}

همیشه hash_equals استفاده کنید — مقایسه‌ی === در برابر حمله‌ی زمانی (timing attack) مقاوم نیست.

امضای وبهوک#

هدر X-Webiro-Signature: sha256=<hex> روی بدنه‌ی خام درخواست (همان رشته‌ای که HTTP body می‌رسد، نه آرایه‌ی decode‌شده) محاسبه می‌شود:

تایید وبهوک
$raw   = file_get_contents('php://input');
$sig  = $_SERVER['HTTP_X_WEBIRO_SIGNATURE'] ?? '';
$calc = 'sha256=' . hash_hmac('sha256', $raw, $secret);

if (!hash_equals($calc, $sig)) {
    http_response_code(400);
    exit;
}
$hook = json_decode($raw, true);

محافظت‌های سمت گیت‌وی#

  • جداسازی پذیرنده‌ها: هر کلید فقط تراکنش‌های خودش را می‌بیند؛ استعلام توکن دیگران 404 است.
  • قفل دامنه: callback_url باید هم‌دامنه با callback_domain پذیرنده باشد.
  • اتصال ResNum: در سامان، شناسه‌ی سفارشِ برگشتی از بانک باید دقیقاً توکن تراکنش ما باشد — جلوی تزریق پارامتر گرفته می‌شود.
  • تایید مبلغ: مبلغ تاییدشده‌ی بانک باید دقیقاً برابر مبلغ تراکنش باشد؛ مغایرت = fail (+ Reverse در سامان).
  • نهایی‌سازی اتمیک: تغییر وضعیت فقط از pending با شرط SQL — callback تکراری اثر دوباره ندارد.
  • Rate limit: پیش‌فرض ۶۰ درخواست API در دقیقه برای هر IP.
  • حریم خصوصی: شماره کارت فقط ماسک‌شده ذخیره می‌شود؛ لاگ‌ها مقادیر حساس را مخفی می‌کنند؛ صفحات بانکی با no-referrer سرو می‌شوند.
  • مسدودسازی وب: config، data، logs، src، sdk و tools با .htaccess از وب خارج هستند.

چک‌لیست امنیتی پذیرنده#

  • مبلغ پرداخت را از دیتابیس خودتان بخوانید — هرگز از $_GET/$_POST کاربر.
  • امضای sig را قبل از هر استفاده تایید کنید و برای مبالغ مهم، status() هم بگیرید.
  • ثبت سفارش را idempotent بنویسید (UPDATE orders SET paid=1 WHERE id=? AND paid=0).
  • کلید secret را فقط در سمت سرور نگه دارید؛ در گیت و لاگ عمومی نگذارید.
  • اگر مبلغ را در callback نشان می‌دهید، آن را با رکورد سفارش خودتان مقایسه کنید.
  • برای endpoint وبهوک، CSRF را غیرفعال کنید (درخواست خارجی است) ولی امضا را الزامی.

مدیریت کلیدها#

  • کلید API (wgr_…) هویت پذیرنده است؛ Secret (wgs_…) قلم امضاست. هر دو در config/config.php.
  • برای تعویض کلید لو‌رفته: مقدار جدید در کانفیگ بگذارید و پذیرنده را موقتاً enabled: false کنید تا جایگزین شود.
  • کلیدهای تولیدشده هرگز در دیتابیس ذخیره نمی‌شوند؛ فقط در کانفیگ — بکاپ کانفیگ را محافظت‌شده نگه دارید.
