Webiro Gateway

تنظیم درگاه‌ها

اعتبارنامه‌ی هر درگاه در config/config.php بخش drivers قرار می‌گیرد. درگاهی که تنظیم نشده باشد به‌صورت خودکار از لیست حذف و در حالت auto استفاده نمی‌شود.

واحد پول: API گیت‌وی با ریال کار می‌کند (ارسال toman هم پذیرفته و خودکار ×۱۰ می‌شود). هر درگاه واحد خودش را دارد (ریال یا تومان) و تبدیل داخلی انجام می‌شود.

زرین‌پال#

مرچنت‌کد را از پنل زرین‌پال (تنظیمات → درگاه‌ها) بردارید. برای تست، sandbox را موقتاً true کنید.

config.php
'zarinpal' => [
    'merchant_id' => 'xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx',
    'sandbox'     => false,
    'currency'    => 'IRR',
],
کد خطای رایج زرین‌پالمعنی
-10مرچنت‌کد نامعتبر
-11مرچنت‌کد فعال نیست (درگاه تایید نشده)
-15 / -16ترمینال در حالت تعلیق است
-50 / -51مغایرت مبلغ یا پرداخت انجام‌نشده در مرحله تایید

زیبال#

مرچنت‌کد را از پنل زیبال بردارید. مقدار zibal (ثابت) سندباکس رسمی زیبال است و بدون پول واقعی کار می‌کند.

config.php
'zibal' => [
    'merchant' => '68f4c0f4-…',   // یا 'zibal' برای سندباکس
],
result زیبالمعنی
100موفق (در verify: تایید شد)
201قبلاً تایید شده (قابل قبول)
202 / 203پرداخت نشده / ناموفق
103مرچنت غیرفعال
106callback نامعتبر

⭐ بانک سامان#

سه مقدار merchant_id (MID)، terminal_id (TID) و password را از پنل پذیرندگی سپ/سامان بردارید. این درگاه برای تایید تراکنش به اکستنشن soap نیاز دارد.

config.php
'saman' => [
    'merchant_id' => '…',
    'terminal_id' => '…',
    'password'    => '…',

    // پیش‌فرض‌ها معمولاً درست‌اند؛ اگر بانک WSDL جدید داده، همین‌جا عوض کنید
    'wsdl_purchase' => 'https://sep.shaparak.ir/Payments/InitPayment.asmx?WSDL',
    'payment_url'   => 'https://sep.shaparak.ir/payment.aspx',
    'wsdl_verify'   => 'https://sep.shaparak.ir/payments/referencepayment.asmx?WSDL',

    // simple = verifyTransaction(RefNum, MID) — حالت رایج پکیج‌های PHP
    // classic = verifyTransaction(RefNum, TID, MID, Password, Amount)
    'verify_mode' => 'simple',
],

سامان و ای‌نماد: سامان ممکن است دامنه‌ی callback را با مالکیت درگاه تطبیق دهد؛ چون callback همیشه روی webiro.ir است (دامنه‌ی درگاه)، این محدودیت به‌صورت پیش‌فرض برطرف است — همین اصل، دلیل اصلی ساختن این گیت‌وی است.

⭐ بانک پاسارگاد#

درگاه نسل جدید پاسارگاد (pep.shaparak.ir/dorsa1). سه مقدار را از پنل پذیرندگی پاسارگاد بردارید:

config.php
'pasargad' => [
    'base_url'        => 'https://pep.shaparak.ir/dorsa1',
    'username'        => '…',
    'password'        => '…',
    'terminal_number' => '…',
],

جریان: دریافت توکن Bearer → خرید → بازگشت با invoiceId → استعلام (payment-inquiry) → تایید نهایی (confirm-transactions). مبلغ ریال است.

آیدی‌پی (IDPay)#

کلید API را از پنل آیدی‌پی بردارید. مبلغ به ریال ارسال می‌شود و سندباکس با هدر X-SANDBOX فعال می‌شود.

config.php
'idpay' => [
    'api_key' => '…',
    'sandbox' => false,
],

'nextpay' => [

    'amount_unit' => 'rial',  // اگر پنل شما تومان بود: 'toman'
],

اسنپ‌پی (خرید قسطی)#

درایور اختصاصی با جریان رسمی اسنپ‌پی: OAuth2 → ایجاد پرداخت قسطی → verify → settle. مقادیر را از پنل پذیرندگان اسنپ‌پی بگیرید:

config.php
'snappay' => [
    'base_url'      => '…',   // از پنل پذیرندگی (مثال استیجینگ در کانفیگ نمونه)
    'client_id'     => '…',
    'client_secret' => '…',
    'username'      => '…',
    'password'      => '…',
],

سبد خرید به‌صورت خودکار از تراکنش ساخته می‌شود و پس از verify، عملیات settle هم اجرا می‌شود (لازمه‌ی اسنپ‌پی).

خرید قسطی — دیجی‌پی، تارا، لندو، قسطا#

مستندات API این سرویس‌ها عمومی نیست و بعد از عقد قرارداد به پذیرنده داده می‌شود. درایور آن‌ها کانفیگ‌محور است (مثل بلوبانک): ساختار purchase → redirect → callback → verify ثابت است و فقط مقادیر را از مستندات خودتان در config.php پر کنید:

config.php — نمونه برای دیجی‌پی (سایر درگاه‌ها هم همین ساختار)
'digipay' => [
    'enabled'         => true,
    'purchase_url'    => 'https://…/create',
    'purchase_headers' => ['Authorization: Bearer …'],
    'payment_url'     => 'https://…/pay/{token}',
    'token_field'     => 'token',
    'callback_token_param'   => 'token',
    'callback_success_param' => 'status',
    'callback_success_values' => ['OK'],
    'verify_url'      => 'https://…/verify',
    'verify_result_field'    => 'result',
    'verify_success_values'  => ['100'],
    'verify_ref_field'       => 'ref_no',
    'verify_amount_field'    => null,  // مثال: 'amount' برای چک مبلغ
],

همین ساختار برای tara، lendo و ghasta هم در کانفیگ نمونه آمده است. (درایور: src/Drivers/BnplDriver.php)

کریپتو — OxaPay#

پرداخت با تتر، بیت‌کوین و ده‌ها رمزارز دیگر روی شبکه‌های TRON، ERC20، BEP20 و… . کلید Merchant را از پنل OxaPay بردارید (docs.oxapay.com). تایید نهایی با وب‌هوک امضاشده‌ی HMAC-SHA512 انجام می‌شود — یعنی وضعیت پرداخت بدون اعتماد به ریدایرکت مرورگر، از خود OxaPay تایید می‌شود.

config.php
'oxapay' => [
    'merchant_key' => '…',
    'currency'     => 'IRT',    // فاکتور به تومان | USD | USDT | …
    'amount_unit'  => 'toman', // واحد currency نسبت به ریال
    'network'      => null,     // مثال: 'TRON' — null = انتخاب پرداخت‌کننده
    'fee_paid_by_payer' => 1,
    'sandbox'      => false,
],

جریان کریپتو: پرداخت‌کننده فاکتور را با رمزارز دلخواهش می‌پردازد. ابتدا وب‌هوک با وضعیت Paying می‌رسد (تراکنش pending می‌ماند)، بعد از تایید شبکه، وب‌هوک Paid می‌رسد و تراکنش نهایی می‌شود. امضای نامعتبر به‌طور کامل نادیده گرفته می‌شود و کم‌پردازی هم تشخیص داده می‌شود.

بلوبانک#

مستندات IPG بلوبانک عمومی نیست و از پنل پذیرندگی بلوبانک دریافت می‌شود. درایور بلوبانک کاملاً کانفیگ‌محور است: آدرس‌ها و نام فیلدها را مطابق مستندات خودتان پر کنید و بعد enabled را true کنید.

config.php — مقادیر نمونه را با مستندات پنل خود جایگزین کنید
'bluebank' => [
    'enabled' => true,

    // ۱) سرویس دریافت توکن (POST JSON)
    'purchase_url'     => 'https://IPG-بلوبانک/api/purchase',
    'purchase_headers' => ['Authorization: Bearer TOKEN_PANEL'],

    // ۲) صفحه پرداخت — {token} جایگزین می‌شود؛ یا فیلد payment_url در پاسخ
    'payment_url' => 'https://IPG-بلوبانک/pay/{token}',
    'token_field' => 'token',

    // ۳) پارامترهای بازگشت بانک به /callback/{token}
    'callback_token_param'    => 'token',
    'callback_success_param'  => 'status',
    'callback_success_values' => ['OK'],

    // ۴) سرویس تایید سمت سرور
    'verify_url'             => 'https://IPG-بلوبانک/api/verify',
    'verify_result_field'    => 'result',
    'verify_success_values'  => ['100'],
    'verify_ref_field'       => 'ref_no',
    'verify_card_field'      => 'card_no',

    'merchant_id' => '…',
],

ساختار فرض‌شده همان الگوی استاندارد توکن‌محور ایرانی است: purchase → redirect → callback → verify. اگر فیلدهای بلوبانک متفاوت است، فقط نام فیلدها را در همین کانفیگ عوض کنید — به کد دست نمی‌زنید. (درایور: src/Drivers/BlueBankDriver.php)

درگاه تست (سندباکس داخلی)#

برای تست اتصال دامنه‌ها بدون پول. صفحه‌ی شبیه‌ساز بانک سه دکمه دارد: پرداخت موفق، ناموفق و انصراف — و بعد از هر کدام، دقیقاً مثل بانک واقعی: callback، verify، به‌روزرسانی وضعیت، وبهوک و ریدایرکت امضاشده اجرا می‌شود.

config.php
'test' => [
    'enabled' => true,   // ⚠ روی پروداکشن false کنید
],

هشدار: درگاه test پول واقعی جابه‌جا نمی‌کند اما تراکنش‌هایش «پرداخت‌شده» ثبت می‌شوند. قبل از عرضه‌ی عمومی، enabled را false کنید تا هیچ دامنه‌ای نتواند از آن استفاده کند.

ترتیب حالت خودکار (auto)#

وقتی "gateway": "auto" می‌فرستید، اولین درگاهِ پیکربندی‌شده از این لیست انتخاب می‌شود — ترتیب را در کانفیگ عوض کنید:

config.php
'payments' => [
    // ...
    'auto_order' => ['saman', 'pasargad', 'zarinpal', 'snappay', 'oxapay', '…'],
],

هر پذیرنده می‌تواند لیست درگاه‌های مجاز خودش را هم داشته باشد (gateways در بخش merchants) — مثلاً فقط زرین‌پال و زیبال.
